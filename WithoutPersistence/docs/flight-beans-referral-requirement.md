# 需求 4：航班查询云豆与邀请订阅奖励

状态：已实现，待启用与真交易验收。

界面名称为「云豆」，图标统一使用银色豆形，适用于余额、云豆明细和邀请奖励入口。

## 套餐发放和使用

| 云端订阅 | 首次购买和每次成功续订发放 |
| --- | --- |
| 月付 | 每个订阅月 20 云豆 |
| 年付 | 每个订阅年一次发放 300 云豆 |

- 每次手动刷新实际请求航班服务并成功取得查询结果，扣 1 云豆。缓存命中和查询失败不扣。
- 接机自动跟踪按航段单独限额，不占手动查询云豆。
- 云豆用完时仍可查看最近航班结果和查询时间。页面显示下次套餐云豆发放日期（有续订安排时）及邀请入口。

## 邀请订阅奖励

| 被邀请人首次成功付费的套餐 | 邀请人获赠 |
| --- | --- |
| 云端月付 | 5 云豆 |
| 云端年付 | 30 云豆 |

- 「我的账号 → 邀请赚云豆」提供邀请链接或邀请码。被邀请人在首次订阅前绑定；订阅验签成功后，邀请人获得奖励，被邀请人仍获得自己的套餐云豆。
- 同一新付费用户只产生一次邀请奖励。续订和恢复购买不重复发奖，首笔交易退款时撤回对应的邀请奖励。发放和撤回显示在云豆明细。


## 发布与回滚

- 应用云豆迁移后，云豆通过 Production 验签交易发放。Sandbox 台账不发正式云豆。现有仍有效的正式订阅按当前周期补发一次。退款同步撤回该笔订阅发放和邀请奖励。
- 先部署迁移和航班代理，在隔离环境用合成验签事件核对余额、失败释放与重复通知。生产环境待正式收费授权后设置 `FLIGHT_BEANS_ENFORCED=true`，将航班卡强制刷新接入账本。回滚时关闭该变量，保留账本和绑定资料。
- 账本有实际到期时间时展示当前周期结束日期。只有验签得到新订阅周期后才入账，期末日期不承诺一定会续订。
