# 需求 4：航班查询云豆与邀请订阅奖励

状态：已实现，待启用与真交易验收。

界面名称为「云豆」，图标统一使用银色豆形，适用于余额、云豆明细和邀请奖励入口。

## 套餐发放和使用

| 云端订阅 | 首次购买和每次成功续订发放 |
| --- | --- |
| 月付 | 每个订阅月 20 云豆 |
| 年付 | 每个订阅年一次发放 300 云豆 |

- 手动刷新与接机自动跟踪共用同一账户余额。实际请求航班服务并成功取得查询结果时，默认扣 2 云豆。缓存命中和查询失败不扣；可用余额不足时跳过付费请求。
- 在云盛应用管理的「云豆设置」调整每次扣豆（1–100）；写入使用现有应用管理授权、近期二次验证及审计。已预留的查询按预留金额结算。
- 云豆用完时仍可查看最近航班结果和查询时间。页面显示下次套餐云豆发放日期（有续订安排时）及邀请入口。

## 邀请订阅奖励

| 被邀请人首次成功付费的套餐 | 邀请人获赠 |
| --- | --- |
| 云端月付 | 5 云豆 |
| 云端年付 | 30 云豆 |

- 「我的账号 → 邀请赚云豆」提供邀请链接或邀请码。被邀请人在首次订阅前绑定；订阅验签成功后，邀请人获得奖励，被邀请人仍获得自己的套餐云豆。
- 同一新付费用户只产生一次邀请奖励。续订和恢复购买不重复发奖，首笔交易退款时撤回对应的邀请奖励。发放和撤回显示在云豆明细。


## 发布与回滚

- 应用云豆迁移后，云豆通过 Production 验签交易发放。Sandbox 台账不发正式云豆。现有仍有效的正式订阅按当前周期补发一次。退款同步撤回该笔订阅发放和邀请奖励。
- 先部署迁移和航班代理，在隔离环境用合成验签事件核对余额、失败释放与重复通知。生产环境待正式收费授权后设置 `FLIGHT_BEANS_ENFORCED=true`，将航班卡强制刷新接入账本。回滚时关闭该变量，保留账本和绑定资料。
- 账本有实际到期时间时展示当前周期结束日期。只有验签得到新订阅周期后才入账，期末日期不承诺一定会续订。

## 2026-11-26 验收基线

- 只读核对正式库交易台账为 28 笔 Sandbox、0 笔 Production。审核测试账号的月付已结束，年付已实际验签入账两笔，其中一笔仍有效。该结果验证真实沙盒月付转年付，并不代表云豆已经入账。
- 云豆隔离回归覆盖首订奖励、乱序续订、同周期恢复、退款去重、已过期的扣豆预留和最后一豆重复预留。Web 回归覆盖输入邀请码、绑定请求和余额明细。
- 整合验收需用隔离的收费候选及隔离后端，用不同的邀请人和新订阅用户核对邀请码绑定、苹果验签、云豆明细、手动刷新和退款。真实 Sandbox 交易不得写入生产云豆。正式扣豆和购买开关需在整合验收及发布授权后启用。
- 免费 1.2(21) 正在走独立审核路线。准备收费候选时，重新核对最后实际公开发放的免费构建及收费分界，不沿用曾经仅为内部测试的构建 18 分界。

### 共用钱包迁移

在已有应用管理及云豆账本的环境中，先应用 `202611270001_shared_flight_bean_wallet.sql`，再部署 `flight-auto-refresh`。手动刷新继续使用原有 RPC，SQL 迁移后读取同一费率。已有预留保留原价，历史流水无需迁移。正式扣豆沿用 `FLIGHT_BEANS_ENFORCED` 开关。

如需暂停扣豆，关闭该开关。如需回到手动 1 豆且自动不扣，先回退自动排程函数，再在应用管理将费率设为 1。保留账本与审计，避免重新解释历史扣款。
