# 到期账号只读设备恢复

已登记的 Web 设备发起恢复并重新验证账号身份。用户选择要替换的旧设备，在重装后的 App 输入一次性配对码。App 需已登录同一账号，服务端以当前登录身份和 App 当前设备标识完成配对。

- 发起时查验到期授权及 Web 设备有效登记，重新验证密码仅用于此操作。服务端签发短时、一次性的随机配对码，数据库只存摘要，并限制发起和失败尝试次数。
- 完成时在事务内按账号加锁，复查账号仍到期、发起设备和被替换设备均有效，以及配对码归属和期限。成功后撤销选定设备，新增只读登记并消费配对码。保留其他设备和原设备上限。已撤销的目标设备不得通过此流程恢复。
- 首版保留发起恢复的 Web 设备作为回退入口。若没有另一条有效登记，保留现有手工支持路径。
- 只读登记单独保存，归档接口校验后才允许读取和导出。在线业务接口和常规设备登记逻辑继续要求原有有效云端授权。订阅恢复后按现有流程登记，不从只读记录直接推导写权限。

## 迁移与回滚

新增私有配对及只读登记表、审计记录和限定用途的服务端接口。客户端不得直接写表。数据库迁移先在隔离环境验证。部署顺序为数据库、服务端、Web 和 App。回滚时先关闭发起和完成入口，再将归档校验恢复为仅接受原登记。保留审计及替换前状态，由管理员按记录逐笔复原受影响的旧登记，避免批量恢复已主动撤销的设备。

## 验收

验证同账号成功替换后旧设备不能读取、新设备可查看及导出、Web 可继续导出、名额不增加。检查新增、编辑、结算、同步及航班功能仍被拒绝。失败用例覆盖跨账号配对、重复使用、过期、错误密码、已撤销设备、并发兑换和期间授权变化。确认失败事务不会撤销旧设备。通过隔离测试后，再用 02 账号和重装后的 A16 iPad 验收实际流程。

## 隔离数据库原型结果

原型改用设备登记表中的 `archive_only` 标记，使旧设备替换继续沿用同一套名额统计和撤销操作。普通云端访问明确排除该标记，订阅恢复后须经过现有正常登记才能清除标记。此实现取代前文独立只读登记表的初步设计。

在本机 PGlite 合成数据库执行原型，验证替换、失败回滚、拒绝重复兑换、名额保持、续订后普通访问仍拒绝，以及正常登记后恢复访问。测试脚本位于 /tmp/trvelma-recovery-pg/check.mjs。原型保留在 verification 下，默认回滚。Web 重新验证、限流、App 配对入口和实际归档导出尚待实现与验收。

## 02 试点部署

用户授权后，将 Web、App、Edge Function 和数据库 RPC 入口限定为 02 测试账号。数据库事务在 Supabase SQL Editor 执行成功，线上函数名为 expired-device-recovery，未登录请求返回 HTTP 401。Web 基于上一生产 ZIP 仅应用本次 Web 差量，版本 20261118-recovery-02-v1 已从正式域名验证。A16 iPad 1.1(14) 已覆盖安装并启动。Web 206 项测试、签名构建与隔离数据库验证通过。

仍需本人输入当前云端密码签发配对码、选择旧 iPad、在新 iPad 兑换并验证导出。停用时先撤销三项 RPC 授权，再将 Web 回滚至 1ffb5fff-d01c-4386-b5cf-1ef7b8a2abe5。若已发生替换，保留只读标记和审计记录，按账号逐笔核对后再决定是否复原旧登记。

## 02 真机验收结果

用户在 Web 验证密码并生成配对码，A16 iPad 兑换后归档立即加载，原合成客户 1 条可见。Web 刷新后仍可读取同一归档。iPad 导出选“保留两者”，生成“TrvelMA-资料备份 3.json”，在文件 App 打开确认含原客户及 read_only=true。整个过程未恢复云端编辑入口。隔离测试覆盖旧设备失效和写权限限制，本轮未以真实业务写入测试。
