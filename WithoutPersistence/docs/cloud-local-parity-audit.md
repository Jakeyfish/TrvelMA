# Local / cloud edition parity audit

Last updated: 2026-10-22

## Comparison rule

The local edition is the presentation and interaction reference. Cloud edition must use the same labels, layout hierarchy, filtering, edit/delete rules, and actions while reading and writing the authenticated account's cloud records. After login, the only intended interface difference is a small account/edition tag beside the username. Account scope and online-only writes must remain intact.

- 发现 `max_devices` 之前只被客户端读取、未计数或限制实际设备。增加开发环境设备登记表/RPC、登录启动登记、退出时释放当前设备，以及云端请求设备标识与 RLS 校验迁移。
- 测试账号 `ystechnology01@yahoo.com` 的开发环境额度现为 2。设备登记迁移已执行；新版 iPad mini 启动后在 `account_devices` 中验证为 1 条活动 iPad 记录。
- 新版已安装至 Tony’s WIFI HOT iPhone。用户解锁后，`devicectl` 成功启动 Wishlist，设备进程正常。迁移应用后再次启动，测试账号 iPhone 的 `last_seen_at` 更新至 02:27 UTC，说明设备注册请求仍成功。镜像连接要求锁定设备；锁屏时画面模糊，用户解锁后镜像会断开，因此当前无法从镜像核验清晰页面。
- 用户确认后，在 `travel-manager-dev` 执行了 `202610220004_enforce_account_device_limit.sql`。只读边界验证结果为：活动 iPhone `true`、活动 iPad `true`、随机未登记设备 `false`；生产项目未改动。
- 复核了云端数据、同步及私有 Storage 请求：PostgREST 和 Storage 请求统一携带 `x-account-device-id`；权益读取与设备登记 RPC 在注册前不依赖该标头，避免新安装无法首次登记。实际 App 启动后登记时间更新，边界函数测试也通过。
- 复核云端客户编辑的 `created_at`：RPC 的 `ON CONFLICT` 更新分支只改业务字段、`updated_at` 和 `deleted_at`，不会覆盖原始 `created_at`；编辑器发出的当前时间不会导致客户创建日期被重置，无需改动。
