# 需求 1：接机航班自动读取与落地记录

状态：已实现，待部署及线上验收。

适用于已绑定航班、待执行的接机行程。以用户选定的接机航段为准，多航段同航班号按接机机场对应的航段处理。由云端执行，手机未打开 App 时也能运行。iOS 和 Web 显示同一份航班更新。

| 设置项（设置 → 航班查询 → 自动读取时间） | 默认值 | 起算依据 |
| --- | --- | --- |
| 国际航班首查 | 提前 60 分钟 | 计划落地时间 |
| 国内航班首查 | 提前 40 分钟 | 计划落地时间 |
| 落地复查（国内、国际共用） | 延后 3 分钟 | 最新预计落地时间 |

- 三项分钟数均可配置。保存后按新设置重新排程尚未执行的查询。
- 每个航段首查一次，复查最多一次。首查已确认落地则直接记录。复查前若系统收到更新的预计落地时间，则据此调整这一次复查的时间。同一航段关联多张订单时共用查询结果。
- 确认落地后保存最终航班状态、实际到达时间（有返回时）以及查询时间。复查仍未确认落地时，保留最后一次查到的状态并标记「待确认」，保留手动刷新入口。
- 更新范围为航班卡和航班记录，订单约定的接客时间保持原值。


## 发布与回滚

1. 先在隔离环境应用两项迁移，验证现有行程读写与账号隔离。机场所在国家和 IANA 时区来自 mwgg/Airports。自动排程使用航班快照中的计划落地时间。只有航班号或旧快照缺少可识别航段、计划落地时间时，需手动查询并选定航班建立排程依据。
2. 部署 `flight-auto-refresh` 和共用上游调用的 `variflight-lookup`，确认匿名调用新函数被拒绝、手动查询仍可用。在 Vault 中配置 `flight_auto_project_url` 和 `flight_auto_refresh_secret`，在工作函数环境中用同一份秘密配置 `FLIGHT_AUTO_REFRESH_SECRET`。最后执行 `supabase/ops/schedule-flight-auto-refresh.sql`，每分钟触发一次，仅在读取到已授权的未完成接机航班时调用提供商。自动与手动查询共用原有配额。
3. 使用隔离测试账号验收两端设置、首查与单次复查、同账号同航段多张单共用查询，以及不修改接客时间。最后才发布客户端。生产数据库未在此开发任务中变更。
4. 回滚时先通过 `cron.unschedule('flight-auto-refresh')` 停止排程，再恢复前一版客户端及手动查询函数。保留三个设置值、已查状态和最终记录。旧客户端可继续读取既有航班字段。
