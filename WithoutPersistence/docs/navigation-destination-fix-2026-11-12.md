# 地址联想与导航目标一致性修复

分支 codex/billing-1.1，iOS 仍为 1.1(14)，待发布 Web 构建 20261112-nav-v1。本轮未提交、部署或修改真实订单。

## 事实与根因边界

- 用户截图：行程起始点是一条门牌/街道地址，Google 路线目的地却是另一处酒店。用户确认通过地址联想候选选择该地址。
- 本地/云端卡片及详情的按钮均将相应行地址值交给 NavigationProvider，没有发现固定酒店、起终点互换或链接复用实现。
- 明确发现：行程及客户地址候选点击仅拼接 title/subtitle，未解析选中 completion 对应的地图地点，也未保留坐标；导航只传文本，让地图再次识别。
- 文本丢失选中地点身份是已确认的实现缺陷；此次 Google 具体为何匹配到那家酒店尚未在真机复现，不把地理解析歧义、旧地图状态等猜测写成确定根因。

## 实现

- 新增 NavigationDestinationStore：针对用户点选的 MKLocalSearchCompletion 发起 MKLocalSearch.Request(completion:)，只接受唯一有效地点坐标，不从多个结果盲选第一条。
- 坐标以完整地址精确键保存在当前账号范围；最多200项、30天有效。南北方向、不同街道/城市不会模糊合并；无坐标、过期、失败、多个结果均不授权自动发起路线。
- 同文字的后选结果覆盖前选；旧异步结果、账号切换、清除资料和取消任务均不能重新写回坐标。缓存清理接入本地及云端本机资料清除，不删除或改写业务记录。
- App 统一 NavigationProvider：已确认地点或显式经纬度用坐标生成驾车路线；旧地址/手输地址未确认坐标时改为地图地点搜索，让用户核对后再开始路线。原地址显示不变，不凭空补坐标。
- Web 统一 safeNavigationURL：显式有效坐标直接导航；文字地址进入地点搜索。起始点、目的地、停靠点及客户常用地址共用规则。Web 不具备 App 本机坐标缓存；缓存不通过现有同步协议传送，其他设备未确认地点时保持安全搜索回退。
- 无数据库结构变更、无新服务密钥、无新增 UI 语言键、无真实地址的外部自动查询。测试只使用合成地址及坐标。

## 验证

- App 完整隔离回归：385项、0失败。新增5项测试覆盖文本只搜索、坐标路线、账号/南北地址隔离、非法及多结果拒绝、解析失败不使用旧坐标、同文字异步乱序、清除/切号后旧结果拒绝。
- Web 完整回归：188项、0失败。新增坐标/文字/空值/非法坐标规则及起点/终点/停靠点/常用地址实际点击处理器测试。
- Release 无签名模拟器构建 BUILD SUCCEEDED；git diff --check 通过。隔离测试没有调用真实 MapKit 查询，也不等于 Google Maps 真机终点核对通过。
- 设备当前离线。该旧订单原先没有保存坐标，需要重新选择同一候选才会生成地点记录；没有自动编辑该真实订单。缓存仅本机可用，重装或另一设备会回退搜索核对。
- 历史1.0.1工作目录存在大量未提交修改且工程版本仍为1.0(7)，本轮只读查看，没有覆盖或将其作为干净正式补丁基线。

## 发布与回退

- 代码可在当前1.1范围提交，尚未提交或发布。真机应先用合成地点确认目标坐标、起终点/停靠点区分，再由用户在旧订单重新点选地址并核对实际 Google 终点。
- 不因本修复开启1.1正式收费或部署未完成的购买逻辑。正式版单独补丁需先确定干净稳定源，不能覆盖已有1.0.1工作。
- 若回退代码，应保留无坐标先搜索的保护，不能为恢复旧交互重新自动路由未核实的文字地址；坐标缓存可按账号清除，不涉及数据库回滚。

参考：[Google Maps URLs](https://developers.google.com/maps/documentation/urls/get-started)、[Apple 搜索选中地点](https://developer.apple.com/documentation/mapkit/interacting-with-nearby-points-of-interest)。
