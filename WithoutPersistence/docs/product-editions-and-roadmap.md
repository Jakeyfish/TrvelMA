# 产品版本与数据边界

## 版本拆分

| 版本 | 数据放置 | 使用方式 | 收费方式建议 |
| --- | --- | --- | --- |
| 单机版 | 只在当前设备的 SwiftData 数据库 | 无需登录、离线可用；提供手动导出/恢复 | 一次性买断 |
| 云端版 | Supabase 账户数据 | 登录后通过网络使用；云端备份 | 月付/年付订阅 |
| 双端同步版 | 同一账户的 Supabase 数据，并缓存到 iOS | iOS 与 Web 使用同一份云端数据；离线修改排队后同步 | 月付/年付订阅的高阶档，或云端版增购项 |

云端同步会持续产生数据库、图片存储、带宽和备份费用，因此不建议把云端能力包含在永久买断里。暂不确定售价、试用期和同步设备数量；先接好权益识别和用量统计，再根据 Supabase 费用决定档位。

## 代码和服务边界

- `LocalDataStore`：单机版读写设备数据库，不能调用网络上传。
- `CloudDataStore`：云端版/同步版访问 Supabase，所有用户记录由 RLS 按 `auth.uid()` 隔离。
- `SyncCoordinator`：仅双端同步版启用，负责离线队列、冲突处理、重试和同步状态。
- `AssetStorage`：头像、名片、收款码、名片二维码等图片放私有对象存储；数据库仅存对象路径和元数据。
- `EntitlementProvider`：从 StoreKit 和服务端校验结果判断 `local`、`cloud`、`sync` 权益。UI 只能展示权益，服务端仍需限制云端 API、Storage 和设备数。
- Web 与 iOS 共用云端数据表和权益规则。不能让 Web 客户端持有 Supabase service-role 密钥。

## 已完成的基础步骤

- 云端账号第一次发现本机资料时，先统计最近一次使用的本机账号资料与旧版未归属资料，再询问默认方式；用户选择后按云端账号记住偏好，可在设置中修改。
- 只有尚未迁移或迁移后又修改过的本机名片、收款方式才会触发确认；云端已有资产不会被误判成本机待上传数据。
- 设备没有待迁移本机资料时直接下载云端内容。
- 可选择自动导入并同步本机资料，或只使用当前云端账号资料；本机原始资料保留在设备上。
- 本地/云端登录说明已更新，并覆盖英语、西班牙语、日语、韩语和繁体中文。
- 业务记录增加本机/云端账户范围；列表查询、同步读取和删除队列都按当前范围过滤。
- 本机账号按邮箱分配独立范围；用户确认后，只迁入最近一次使用的本机账号资料和旧版未归属记录，其他本机账号资料仍留在设备上。
- SwiftData 持久化模型清单已集中到 `AppDataSchema`，容器工厂可以为相同模型创建不同命名的数据库文件。
- 已准备保留旧库、可重复运行的 SwiftData 迁移器：按本机/云端范围复制客户、客户子项、旅行社、行程、删除队列、本机账号和登录资料，并核对稳定 ID。导入已存在的云端客户时保留当前云端内容，不再因子项内容不同而误报失败。
- 名片和收款方式现按本机账号 UUID 与云端账号邮箱分区；旧版邮箱键数据会非破坏性复制到本机区，云端同步只读写云端区。本机资产导入云端仍需用户确认，且本机原件保留。
- 启动时创建独立的 `local.store` 与 `cloud.store`，先执行旧 `default.store` 的可重试拆分迁移并核对记录，再依据登录模式选择活动容器；显式导入会把本机资料复制到云端缓存，保留本机原件。

SwiftData 现拆成本机与云端缓存两个物理数据库文件；云端缓存仍是设备本地副本，不代表远端网络已连接成功。旧版没有账号归属的数据会先进入本机库，再由用户选择是否导入云端。用户反馈数据测试目前没有问题；这记录为测试设备验收通过，不代表生产数据已迁移。名片与收款图片已接入 Storage 客户端流程；远端开发项目的私有 bucket 和 4 条用户目录访问策略已创建，并已查询确认。
